# Цифровой двойник Sesame — спецификация

Дата: 2026-11-27. Ветка: `devkit-powerbank` (форк tier777/sesame-robot).

## Зачем

1. **Для v1, сразу.** Вчера на подбор углов одной ноги ушло два часа: бедро упиралось в корпус на 155°,
   потому что качалка была надета со сдвигом, а какой канал бедро, а какой лапа, выяснялось руками.
   Двойник должен заранее говорить, куда смотрит каждый сустав при каждом угле, где упоры,
   и давать подбирать позы на экране, а не на живых сервах.
2. **Для прошивки.** Какие сервы как двигаются в каждой позе Sesame, диапазоны, скорости, нагрузка,
   устойчивость — числами и видео.
3. **Для v2.** Корпус v2 (отдельная спецификация потом) строится из тех же параметров и каждое изменение
   сначала проверяется в двойнике, потом печатается.

## Что пользователь сказал / что принято

Сказано: двойник сначала, на геометрии v1; длины лап и тип ног (2 степени свободы, бедро — вертикальная ось,
лапа — горизонтальная) не меняем; бёдра в v2 раздвигаются примерно на 8 мм вдоль корпуса; нужны максимальные
значения и характер движения каждой сервы для прошивки; плата и питание пока не решены.

Принято без отдельного обсуждения: Python + MuJoCo; геометрия из STEP-сборки автора; позы берутся из кода прошивки,
а не переписываются руками.

## Границы

Входит: геометрия и массы v1, кинематика, физика, проигрывание всех поз прошивки, отчёт и видео,
калибровочный помощник, редактор поз с зеркалированием на живого робота.

Не входит: корпус v2, правки прошивки, выбор платы и питания (двойник только даёт цифры тока).

## Состав

```
hardware/v2/twin/
  params.py          — все числа: оси серв, звенья, массы, приводы, перевод углов, зубцы шлица
  geometry.py        — читает STEP автора, раскладывает детали по звеньям, пишет сетки
  firmware_trace/    — заглушка Arduino + сборка movement-sequences.h на компьютере → запись поз
  model.py           — собирает MJCF (модель MuJoCo) из params + сеток
  simulate.py        — проигрывает записи поз, пишет логи
  report.py          — report.md, графики, видео
  calibrate.py       — калибровочный помощник
  poser.py           — редактор поз (окно MuJoCo с ползунками) + зеркалирование на робота
  meshes/  traces/  out/   — генерируемое, в git только то, что нужно для отчёта
hardware/v2/tools/twin.sh — полная пересборка одной командой
hardware/v2/.venv         — окружение Python, в .gitignore
```

## 1. Геометрия (`geometry.py`)

- Источник — `hardware/cad/Sesame-ESP32-v122.step` (сборка автора, ~220 вхождений, сервы на своих местах).
  Чтение через OCP (`cadquery-ocp`).
- Для каждой из 8 серв находится ось вала: центр и направление цилиндра вала в модели сервы
  с учётом её положения в сборке.
- Детали раскладываются по 9 звеньям: корпус (рама, крышки, электроника), 4 бедра (R1, R2, L1, L2
  вместе с сервой лапы, если она едет на бедре), 4 лапы (R3, R4, L3, L4). Правило: деталь принадлежит звену,
  к которому она прикручена в сборке; спорные случаи перечисляются в `params.py` явно.
- Выход: сетки звеньев для картинки (STL, упрощённые до ~20 тыс. треугольников) и выпуклые части
  для столкновений (выпуклая оболочка каждой детали; деталь с сильной вогнутостью делится на 2–4 выпуклые части).
- Проверка: оси, найденные в STEP, сравниваются с осями, снятыми с STL в `hardware/printing/stl/`
  (крышки, рама), — расхождение не больше 0,5 мм.

## 2. Параметры (`params.py`)

- Оси и звенья — из шага 1, записываются числами, чтобы v2 мог их менять (разнос бёдер и т. д.).
- Массы: детали — объём × плотность (PETG 1,27 г/см³, PLA 1,24 г/см³, заполнение учитывается коэффициентом),
  MG90S 13,4 г, DevKit 10 г, OLED 3 г, Mini560 3 г, отсек 2×14500 с банками 50 г — с положением в корпусе
  (сейчас на спине, на седле).
- Приводы MG90S: ход 0–180°, предельный момент 0,2 Н·м, скорость 60° за 0,1 с, мёртвая зона 1°.
- Перевод «угол прошивки → угол сустава»: ноль и направление для каждого канала.
  Начальные значения — по схеме автора `docs/build-guide/assets/sesame-angle-guide.png` и
  `reference-configuration.png` (все сервы на 90°); сверка — по напечатанной ноге (раздел 7).
- `servoSubtrim` из прошивки читается и прибавляется, как в `setServoAngle` (с обрезкой 0–180°).
- Шлиц качалки: число зубцов (`spline_teeth`, по умолчанию 20, пересчитать на настоящей качалке) —
  нужно калибровочному помощнику.

## 3. Позы из прошивки (`firmware_trace/`)

- `movement-sequences.h` собирается `clang++` на компьютере вместе с заглушкой `Arduino.h`:
  - `setServoAngle(ch, a)` пишет `(t, ch, a)` и, как в прошивке, сдвигает время на `motorCurrentDelay` (20 мс);
  - `delayWithFace(ms)` сдвигает время; `setFace*`, `Serial` — пустые;
  - `pressingCheck` пропускает `walkCycles` (10) полных циклов ходьбы, потом «стоп» и stand, как в прошивке;
  - `frameDelay` 100 мс, `walkCycles` 10, `motorCurrentDelay` 20 мс — по умолчанию из прошивки, переопределяются.
- Выход: `traces/<поза>.json` — список `(t_мс, канал, угол)` для всех 19 поз
  (rest, stand, wave, dance, swim, point, pushup, bow, cute, freaky, worm, shake, shrug, dead, crab,
  walk, walk backward, turn left, turn right). Поза, которую не удалось собрать, отмечается в отчёте
  и не останавливает остальные.
- Прошивка не меняется: заглушка лежит рядом и подключается только при сборке на компьютере.

## 4. Физика (`model.py`, `simulate.py`)

- MJCF: корпус — свободное тело, бедро и лапа — шарниры по осям из шага 1, пределы 0–180° в углах прошивки.
- Привод — позиционный, момент обрезан до 0,2 Н·м; цель двигается к углу из записи не быстрее 600°/с.
- Пол — плоскость, трение лапа–пол 0,8. Столкновения: лапы и бёдра с полом, бёдра и лапы с корпусом и друг с другом.
- Каждая поза начинается со stand на полу после 0,5 с успокоения, дальше идёт запись.
- Лог на каждом шаге 2 мс: углы (цель и факт), моменты, контакты (какие пары, с какой силой), центр масс,
  точки опоры, положение и наклон корпуса.

## 5. Отчёт (`report.py`)

`out/report.md` и `out/videos/<поза>.mp4` (вид сбоку-сверху, 30 кадров/с):

- по каждой серве и позе: мин/макс угол (прошивка и сустав), пиковая скорость, пиковый и средний момент в % от 0,2 Н·м,
  время в упоре (момент на пределе дольше 0,2 с);
- столкновения: пара деталей, поза, угол каждой сервы в момент касания;
- устойчивость: минимальное расстояние от проекции центра масс до края опоры в каждой позе;
  падение (корпус наклонился больше 45°) — отдельной строкой;
- ход на шаге: смещение корпуса за цикл walk и turn;
- ток: оценка `I = 0,1 А + 3,3 А/(Н·м) × |момент|` на серву (линейная модель MG90S: 0,1 А без нагрузки,
  ~0,75 А в упоре), сумма по 8 сервам — пик и среднее для каждой позы.

## 6. Калибровочный помощник (`calibrate.py`)

- Для каждой сервы: картинка ноги в положениях 0°, 90°, 180° в углах прошивки — куда должно смотреть бедро и лапа.
- Упоры: по геометрии считает, при каком угле каждое звено касается корпуса или соседей — это безопасный диапазон для прошивки.
- Сдвиг качалки: вводишь замеренный упор (например «R1 упирается на 155°»), помощник сравнивает с расчётным
  и говорит «переодень на N зубцов в сторону …» и какой остаток уйдёт в `servoSubtrim`.
- Каналы: печатает таблицу «канал → сустав → вывод платы» из прошивки, чтобы бедро и лапу не путать.

## 7. Редактор поз и зеркало (`poser.py`)

- Окно MuJoCo с 8 ползунками в углах прошивки; столкновения подсвечиваются, центр масс и опора рисуются на полу.
- Кнопка «Записать кадр» копит кадры; «Экспорт» печатает готовую функцию C++ в стиле `movement-sequences.h`
  (`setServoAngle(R1, 135); ... delayWithFace(300);`).
- Зеркало на живого робота (включается отдельно): последовательный порт 115200,
  протокол основной прошивки `«<канал> <угол>»` или тестера `«<канал>,<угол>»` — выбирается ключом.
  Робот повторяет ползунки; угол вне безопасного диапазона из раздела 6 не отправляется.
- Сверка с реальностью: на напечатанной ноге R1+R3 замеряются упор бедра и угол лапы при 0/90/180,
  сравниваются с двойником, разница идёт в `params.py`. Готово, когда двойник совпадает с ногой в пределах 5°.

## Окружение

- Python 3.12 через Homebrew, окружение `hardware/v2/.venv`.
- Пакеты: `mujoco`, `numpy`, `cadquery-ocp`, `trimesh`, `imageio[ffmpeg]`, `matplotlib`.
- `clang++` из Xcode Command Line Tools для записи поз.
- `bash hardware/v2/tools/twin.sh` — геометрия → записи поз → модель → симуляция → отчёт; падает с понятным
  сообщением на первом сломанном шаге.

## Проверки

- Геометрия: оси из STEP против STL — до 0,5 мм.
- Записи поз: stand даёт ровно 8 вызовов с углами из прошивки; длительность wave = сумма `delayWithFace` из кода + 20 мс × число вызовов `setServoAngle`.
- Физика: в stand робот стоит 5 с, корпус не наклоняется больше 2°, лапы не проскальзывают больше 1 мм.
- Реальность: нога R1+R3 — совпадение в пределах 5° (раздел 7).

## Готово, когда

- `twin.sh` проходит целиком, `report.md` и видео есть для всех поз, которые собрались.
- Таблица по каждой серве — диапазоны, скорости, моменты, упоры — есть в отчёте.
- Калибровочный помощник выдаёт по замеру «155° у R1» число зубцов и подстройку.
- Редактор поз двигает ногу на столе через зеркало и экспортирует функцию для прошивки.
